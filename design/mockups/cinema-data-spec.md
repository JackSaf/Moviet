# Cinema + билеты: дизайн под сохранённые ответы OMDb

Дата: 26 октября 2026. Основание: `../api-samples/README.md` и JSON в той же папке. Повторные запросы к API и проверки постеров не выполнялись. Это адаптация дизайна; Android-код и база не менялись.

## Выбранное направление

Сохраняем тёмный Cinema и билеты в избранном. Основной сценарий: поиск → список результатов → фильм → сохранение билета. Кинолента и сворачивание афиши остаются отдельными неутверждёнными исследованиями. Новый макет `07-cinema-real-data.png` заменяет вымышленные поля ранних концептов для дальнейшей проработки.

## Поиск

Вертикальный список с портретными постерами. Каждый результат содержит:

| Элемент | Данные | Поведение |
| --- | --- | --- |
| Название | `Title` | Оригинальный текст ответа. Несколько строк; в списке допустимо многоточие, полное название доступно в деталях. |
| Год | `Year` | Строка, включая диапазон `1992–1995`. Не приводить к одному числу. |
| Тип | `Type` | Локальные подписи «Фильм», «Сериал», «Эпизод» для известных значений. |
| Постер | `Poster` | Портретная рамка около 2:3. При недоступности — спокойная заглушка; название и действия остаются видимыми. |
| Закладка | Локальное состояние по `imdbID` | Добавление и удаление из избранного отдельной кнопкой. |
| Число результатов | `totalResults` | Показывать после успешного ответа. В сохранённом примере Batman — 648. |

Рейтинга, жанра, сюжета и длительности в поисковых карточках нет. Отдельные запросы деталей ради каждой строки для базового дизайна не нужны.

Стартовый экран предлагает ввести название. Секции «Популярное», «В тренде», редакционные подборки и похожие фильмы не входят в этот вариант: в сохранённом контракте нет их источника. Доступные фильтры — тип и, при необходимости, год. Жанровые чипы используются только как сведения в деталях.

Поиск по русским названиям не обещаем. Названия из API сохраняют исходный язык. При затруднении предлагаем уточнить запрос или попробовать оригинальное название; один сохранённый ошибочный ответ не означает, что кириллица всегда запрещена.

### Реклама и выдача

По требованиям тестового нужен отдельный native ad item. В макете показан визуально отделённый блок с явной меткой «Реклама», без кинобилета и кнопки избранного. Это иллюстрация места для рекламы, а не настоящий рекламный материал.

Точная трактовка индексов 1 и 3 остаётся открытым вопросом из `docs/PROJECT.md`; макет не утверждает правило вставки. Счётчик результатов считает фильмы API, а не рекламные элементы. Пагинация продолжает список; загрузка и ошибка следующей страницы показываются в его конце, сохраняя уже полученные карточки.

## Билет в избранном

Базовый билет полноценен сразу после сохранения результата поиска:

1. Мини-постер слева, сохраняющий портретные пропорции.
2. Название в центре, ниже год или диапазон и тип.
3. Янтарный корешок справа, отделённый перфорацией, с явной кнопкой закладки.

Высота билета определяется содержимым. Длинные названия могут занимать три и более строк; метаданные не перекрываются. Базовая высота области нажатия — не менее 48 dp. Перфорация и вырезы декоративные и не сокращают область кнопки. В билете нет вымышленных рейтингов, мест, сеансов, цен, QR-кодов и серийных номеров.

Примеры базовых билетов на макете взяты из `search-batman-page-1.json`:

- Batman Begins — 2005 · Фильм.
- Batman: The Animated Series — 1992–1995 · Сериал.
- Batman v Superman: Dawn of Justice (Ultimate Edition) — 2016 · Фильм.

Дополнительные сведения допускаются только при наличии локально сохранённых подробностей. Например, для Interstellar можно добавить IMDb 8.7 и 2 ч 49 мин, если эти поля действительно сохранены. Базовый вариант обходится без них и не резервирует пустые строки или бейджи.

Для работы избранного офлайн будущая модель хранения должна включать `imdbID`, `Title`, `Year`, `Type` и доступный адрес постера. Кешированные подробности — отдельное необязательное расширение. Наличие адреса картинки само по себе не гарантирует доступность постера офлайн, поэтому заглушка остаётся обязательной.

### Сохранение и удаление

Состояние закладки меняется сразу. Короткая анимация корешка или появления билета — ориентировочно 220–320 мс, с учётом системного уменьшения движения. Уведомление содержит действие «Отменить»; после удаления восстанавливаются сам фильм и его место в списке. Уведомление не перекрывает основную навигацию. Подпись «Сохранить билет» допустима как часть метафоры; действие остаётся обычным сохранением в избранное.

## Экран фильма

Сведения берутся из ответа подробностей по ID. Сначала портретный постер и название, затем метаданные, сохранение и текстовые блоки. В качестве атмосферного фона допустим приглушённый цвет из постера. Отдельного широкого кадра, трейлера или фотографий актёров источник не предоставил.

На макете показан Interstellar из `details-interstellar.json`:

- Название: Interstellar; год: 2014; тип: Фильм.
- Длительность: `169 min` → «2 ч 49 мин».
- Возрастная категория источника: PG-13, без перевода в местную возрастную классификацию.
- Основная оценка: IMDb 8.7.
- Жанры: Adventure, Sci-Fi — сохраняем язык внешних данных, пока не введён явный словарь локализации.
- Сюжет: начало оригинального английского `Plot`, свёрнутое до нескольких строк, затем «Читать дальше».
- Режиссёр: Christopher Nolan.
- Актёры: Matthew McConaughey, Anne Hathaway, Jessica Chastain — текстовые имена.

Дополнительные оценки располагаются ниже главного содержания и только при наличии: Rotten Tomatoes 73%, Metacritic 74/100. Название источника и единица оценки обязательны: эти шкалы не взаимозаменяемы.

Для Breaking Bad используем 2008–2013, «Сериал», TV-MA, IMDb 9.5, 5 сезонов. `Runtime=49 min` допустимо показать как «Длительность: 49 мин» без утверждения, что это длительность всех сезонов или подтверждённая длительность каждого эпизода. Director и Metascore отсутствуют: соответствующих строк нет. В `Ratings` есть два источника, поэтому третьего пустого бейджа нет.

`N/A`, отсутствующие поля и пустые коллекции скрываются. Пользователь не видит технический текст `N/A`. Оценка 0 не используется как замена отсутствующей оценке.

## Состояния

| Состояние | Представление |
| --- | --- |
| До запроса | «Найди своё кино», поле ввода; без выдуманной выдачи. |
| Первая загрузка | Спокойные скелетоны строк с реальными пропорциями постера. |
| Movie not found! | «Ничего не найдено» и предложение изменить запрос. |
| Too many results. | «Уточните запрос» и подсказка попробовать более точное или оригинальное название. Это не пустая выдача. |
| Сбой сети | Сообщение и «Повторить»; введённый запрос остаётся. |
| Ошибка следующей страницы | Компактное состояние внизу списка с повтором; загруженные результаты сохраняются. |
| Нет постера / ошибка картинки | Нейтральная рамка с символом кино; текст и закладка доступны. |
| Пустое избранное | Контур билета, «Здесь будут ваши фильмы», переход к поиску. |
| Нет подробностей | Показывать уже известные название/год/тип/постер; состояние загрузки или ошибка с повтором относится к дополнительным данным. |

HTTP 200 не определяет визуальное состояние успеха: слой данных учитывает `Response` и `Error` из сохранённого контракта.

## Материалы и границы

Обновлённый макет собран как интерактивный интерфейс `cinema-api.html` и показан в чате. `07-cinema-real-data.png` — его обзорный снимок с тремя экранами. После отказа автоматического фильтра image_gen генерация не использовалась для финального результата. Постеры в макете — условная графика; реальные URL картинок не загружались и не проверялись.

Текстовые значения подставлены непосредственно из сохранённых JSON: первая страница поиска Batman и три ответа подробностей. В интерактивном просмотре поиск и фильтр работают по этому локальному набору, а число 648 воспроизводит totalResults исходного ответа. Для фильмов, у которых нет примера подробностей, показаны только известные базовые поля. Проверка не является сетевым тестированием API.

Проверены: точные поля примеров, отсутствие оценок в поиске и базовых билетах, диапазон лет сериала, раскрытие полного сюжета, сохранение/удаление с восстановлением позиции через отмену, переходы между экранами, длинное название при ширине окна 320 px. Ошибок JavaScript при проверке не обнаружено.

Ранние изображения и интерактивный скетч `cinema-motion.html` остаются исследованиями движения с демонстрационными данными. При дальнейшем проектировании состав полей определяется этой спецификацией и новым макетом.
