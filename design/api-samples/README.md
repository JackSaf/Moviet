# OMDb: реальные данные для дизайна

Проверено 26 октября 2026 года семью HTTPS-запросами с пользовательским ключом. JSON рядом — ответы API на момент проверки; рейтинги, количество голосов, результаты и постеры могут меняться. Ключ хранится только в игнорируемом `secrets.properties` и в примеры не включён. Android-код не изменён, запросы в приложение пока не интегрированы.

## Поиск

`s=Batman&page=1` и `s=Batman&page=2`: HTTP 200, по 10 элементов на страницу, `totalResults="648"`. Страницы начинаются с 1. Примеры ответов: `search-batman-page-1.json`, `search-batman-page-2.json`.

Каждый результат содержит только `Title`, `Year`, `imdbID`, `Type`, `Poster`. В выдаче встречаются фильмы и сериалы. Год сериала бывает диапазоном, например `1992–1995`. Есть очень длинные названия — например `Batman v Superman: Dawn of Justice (Ultimate Edition)`.

Рейтинг, жанр и длительность в поиске отсутствуют. Для рейтинга на каждой карточке потребуются дополнительные запросы подробностей и кеширование. Базовую сетку поиска можно строить из постера, названия, года, типа и локальной кнопки избранного. Не резервировать обязательное место под рейтинг, если он ещё не загружен.

## Подробности

Запросы: `i=tt0816692&plot=full`, `i=tt0083658&plot=full`, `i=tt0903747&plot=full`.

| Поле | Interstellar | Blade Runner | Breaking Bad |
| --- | --- | --- | --- |
| Год | 2014 | 1982 | 2008–2013 |
| Тип | movie | movie | series |
| Длительность из API | 169 min | 117 min | 49 min |
| Возрастная категория | PG-13 | R | TV-MA |
| IMDb | 8.7/10 | 8.1/10 | 9.5/10 |
| Rotten Tomatoes | 73% | 89% | 96% |
| Metacritic | 74/100 | 84/100 | отсутствует |
| Сезоны | отсутствует | отсутствует | 5 |

Возрастная категория — значение источника: не преобразовывать `PG-13` или `TV-MA` в местный возрастной рейтинг без отдельного правила. Длительность сериала не подписывать как общую длительность всех сезонов.

Дополнительно пришли сюжет (`Plot`), жанры, режиссёр, сценаристы, актёры, дата премьеры, языки, страны, награды и число голосов IMDb. У фильмов есть кассовые сборы `BoxOffice`. Актёры и авторы — строки имён: отдельных фото и биографий в проверенных ответах нет.

`Plot` с `plot=full` содержит 739 символов у Interstellar и 1721 у Blade Runner: описание стоит сворачивать с действием «Читать дальше». В этих примерах названия, сюжет и метаданные на английском; язык интерфейса не означает локализацию данных.

Набор `Ratings` различается: три источника у фильмов, два у Breaking Bad. Не показывать пустые бейджи. `DVD`, `Production`, `Website` у обоих фильмов равны `N/A`; у сериала `Director` и `Metascore` равны `N/A`, а некоторые поля фильмов вообще отсутствуют. Отсутствующие значения скрывать, не выводить пользователю `N/A`.

## Что использовать в Cinema и билетах

- Поиск: портретный постер, название, год или диапазон лет, отметка типа, закладка. Проверенные URL ведут на портретные постеры Amazon; работоспособность самих изображений отдельно не проверялась.
- Экран фильма: крупный постер, название, строка года/длительности/категории, основной рейтинг IMDb, жанры, сюжет, актёры и режиссёр. Дополнительные оценки и награды — второстепенный блок, только при наличии.
- Билет в избранном: мини-постер, название, год, закладка на корешке; рейтинг и длительность можно добавить, если подробности уже получены и сохранены локально.
- Декоративный фон можно получить из постера. Отдельных широких кадров, трейлеров и фотографий актёров в проверенных ответах нет; для широкого фона использовать аккуратную обработку постера, учитывая его разрешение.
- Секции «Популярное»/«В тренде» и глобальный поиск по жанру не описаны в публичном контракте OMDb. Жанр из подробностей подходит для метки фильма, но не подтверждает наличие такого поискового фильтра. Из параметров поиска документированы название, тип и год.

## Ошибки и ограничения, которые проверили

- `s=moviet_no_such_title_7b9e31`: HTTP 200, `Response="False"`, `Error="Movie not found!"`. Для UI — пустой результат с предложением изменить запрос.
- `s=Интерстеллар` (URL-encoded): HTTP 200, `Response="False"`, `Error="Too many results."`. Один пример не доказывает поведение всей кириллицы, но показывает, что нельзя обещать корректный поиск по русским названиям. Для такой ошибки можно предложить уточнить запрос или попробовать оригинальное название.
- HTTP 200 не гарантирует успех: нужно проверять `Response` и `Error`.
- Отсутствующий постер в этой выборке не встретился. Заглушка всё равно нужна при ошибке загрузки или недоступном значении; этот сценарий здесь не проверен.
- Не проверялись последняя страница, лимит запросов, полнота базы и все сочетания поисковых фильтров.

Официальный контракт параметров: [OMDb API](https://www.omdbapi.com/). Поля и конкретные значения выше подтверждены сохранёнными ответами, а не макетами.

## Проверка пустого поиска — 27 октября 2026

По просьбе пользователя выполнены ещё два HTTPS-запроса с настроенным ключом проекта:

| Параметры без ключа | HTTP | Ответ |
| --- | --- | --- |
| `s=&page=1` | 200 | `{"Response":"False","Error":"Incorrect IMDb ID."}` |
| `page=1` (параметр `s` отсутствует) | 200 | `{"Response":"False","Error":"Incorrect IMDb ID."}` |

Полей `Search` и `totalResults` в обоих ответах нет. Сохранены `search-empty-query.json`, `search-missing-query.json` и `empty-search-check.json` с параметрами, статусами и временем проверки; ключ не сохранён.

Пустой или отсутствующий поисковый параметр в этой проверке не вернул каталог фильмов. Это отличается от выполненного поиска без совпадений (`Movie not found!`). Пустой ввод в приложении не следует показывать как эту серверную ошибку.

Стартовый экран с фильмами остаётся продуктовым вариантом: можно отдельно определить небольшую подборку IMDb ID и получать сведения о каждом фильме через запрос подробностей, либо восстанавливать предыдущую выдачу после первого поиска. Подборка и сохранение предыдущей выдачи этой проверкой не реализованы. Текущий ViewModel по-прежнему не отправляет пустые запросы.
